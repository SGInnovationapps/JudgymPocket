# JudgymPocket

演技動画を見ながら減点ボタンを押すと、押した時刻の 0.5 秒前を切り出して画面下に並べ、Eスコアを自動計算する体操採点アプリ。採点が終わったら、減点スタンプを焼き込んだ動画として書き出せる。

ビルド不要。`index.html` を開くだけで動く単一ファイル構成。

## 使い方

ヘッダーの **E採点 / D算出** で画面を切り替える。動画は共通なので、1本の演技に対して両方を続けて採点できる。

### E採点（減点）

1. 上部から演技動画を選ぶ（スマホのカメラロールから選択可）
2. 再生しながら `-0.3` `-0.5` `-0.1` `-1.0` を押す
3. 押した 0.5 秒前のフレームが下部に並ぶ。サムネイルをタップするとその位置に戻る。右上の × で取り消し
4. Eスコア（10 − 減点合計）は右下にリアルタイム表示
5. 「保存」で結果を確認。そこから「スタンプ入り動画を書き出す」で合成動画を生成し、共有シートから写真アプリに保存できる

書き出した動画は、左上に最終Eスコアが大きく入り、減点スタンプは演技の邪魔にならないよう右上に小さく表示される。

### スクリーンショットの保存

- 1枚ずつ: サムネイルをタップ → 「この画像を保存」（動画の元解像度で切り出し、減点タグと時刻を焼き込む）
- まとめて: メニューの「スクショを全部保存」（共有シートに一括で渡す。非対応環境では順に個別ダウンロード）
- 一覧として: メニューの「スクショを1枚の一覧画像で保存」（全カットとEスコアを1枚の画像にまとめる）

右上のメニューから、切り出し位置（既定 0.5 秒前）、スタンプの表示時間、Dスコアの控えを変更できる。

キーボード操作（PC）: `Space` 再生/一時停止、`1`〜`4` 各減点。

### D算出

演技に合わせて、左のグループ（Ⅰ〜Ⅳ）と右の難度（A〜I）をタップすると `ⅠA` `ⅡB` の形で下部に記録される。**順序はどちらが先でもよい**（片方を押すと黄色く選択状態になり、もう片方を押した時点で確定する）。記録はタップでその位置の映像へ移動、右上の × で削除。

「算出」で内訳シートが開く。計算は次の順で行う。

1. 同一グループは難度の高いものから 4 つを残し、5 つめ以降を削除する。同難度なら出現順が早いものを残す
2. 終末技（グループⅣ）について、難度点とグループ点（上限 0.5）を加算する
3. 残りの技から難度の高い順に 7 技を選び、難度点を加算する
4. カウントされた技にグループⅠがあれば、グループ点 0.5 を加算する
5. カウントされた技のグループⅡ・Ⅲについて、D 難度以上があれば 0.5、A〜C 難度のみなら 0.3、なければ 0.0 を加算する
6. 難度点とグループ点の合計を D スコアとする

**グループⅣは 1 演技につき 1 技**なので、2 回目以降を押すと前の終末技が新しいものに置き換わる（置き換えたことを画面下部に通知する）。

内訳シートでは、カウントされた技、8 技を超過した技、①で切り捨てられた技、グループ点の根拠が全て表示される。「Eスコアの控えに反映」を押すと、設定の D スコア欄に値が入り、E採点の結果に合計として併記される。

なお計算は内部で 0.1 = 1 の整数として処理しているため、小数の丸め誤差は発生しない。グループⅣが無い場合は終末技のボーナスが付かず、カウントは 7 技のみになる。

## ホーム画面に追加

HTTPS 上で開き、iPhone は共有 → 「ホーム画面に追加」、Android はメニューの「ホーム画面に追加」または Chrome の「アプリをインストール」。
アイコンとアプリ名 **JudgymPocket** が登録され、Service Worker により 2 回目以降はオフラインでも起動する（動画の書き出し処理もすべて端末内で完結し、サーバーには何も送信しない）。

### アイコンが出ないとき

メニューの **「インストール診断」** を開くと、原因を項目ごとに判定する。よくある原因は次の通り。

| 症状 | 原因 |
|---|---|
| ✕ 配信方法 | `file://` やローカルプレビューで開いている。https で配信しないとインストール扱いにならず、ただのショートカット（灰色の地球アイコン）になる |
| ✕ manifest の取得に失敗 | ファイル名の誤り、`icons/` を push し忘れ、大文字小文字の違い（GitHub Pages は区別する） |
| ✕ アイコンが取得できない | 同上。`icons/` フォルダがリポジトリに入っているか確認 |
| ! まだ通知が来ていない | Chrome は数秒〜十数秒の閲覧のあとにインストール可否を判定する。再読み込みして少し待ってから、もう一度診断する |

なお manifest は `.webmanifest` ではなく **`manifest.json`** にしてある。GitHub Pages が `.webmanifest` を正しい Content-Type で返さず、Android で無視される事例があるため。

## GitHub Pages で公開する

```bash
git init
git add .
git commit -m "JudgymPocket"
git branch -M main
git remote add origin https://github.com/<ユーザー名>/judgympocket.git
git push -u origin main
```

リポジトリの Settings → Pages → Source を `Deploy from a branch`、Branch を `main` / `(root)` に設定。数分後に `https://<ユーザー名>.github.io/judgympocket/` で公開される。

サブディレクトリ配信を前提に、パスはすべて相対パス（`./`）で書いてある。ルート直下に置く場合もそのままで動く。

## ファイル構成

```
.
├── index.html              アプリ本体（HTML/CSS/JS すべて内包）
├── manifest.json    アプリ名・アイコン・表示モード
├── sw.js                   オフライン用 Service Worker
├── .nojekyll               GitHub Pages の Jekyll 処理を無効化
└── icons/
    ├── icon-192.png / icon-512.png
    ├── icon-maskable-192.png / icon-maskable-512.png   Android の丸型・角丸切り抜き用
    ├── apple-touch-icon.png                            iOS ホーム画面用（180px）
    ├── favicon.ico / favicon-32.png
    └── icon.svg                                        元データ
```

## 更新するとき

`index.html` を変更したら、`sw.js` 冒頭の `CACHE` の版番号（`judgympocket-v1` → `v2`）を上げる。上げないと古いキャッシュが表示され続ける。

## 動画書き出しについての注意

書き出しは Canvas + MediaRecorder による等倍のリアルタイム合成。45 秒の動画なら書き出しにも 45 秒かかり、再エンコードのぶん多少画質が落ちる。出力形式は端末依存で、MP4 が使えない環境では WebM になる。

合成される内容は、左上に最終Eスコア（Dスコアがあれば合計も併記）、右上に減点スタンプ、右下に難度スタンプ。スタンプはいずれも記録した時刻の 0.5 秒前から表示される。

### うまく書き出せないとき

シート内に端末・形式・音声・データ量・停止理由のログが出るので、それを見れば原因が分かる。実装上は次の対策を入れてある。

- **開始ボタンを分けている**: Safari は非同期処理を挟むとユーザー操作の権限が切れて `play()` が拒否される。開始ボタンのタップから直接再生を始めることで回避している
- **停止の多重化**: 描画ループのほか `ended` イベントと 0.5 秒ごとの監視を併用し、再生が止まった場合も必ず録画を終了させる
- **画面スリープの抑止**: Wake Lock API に対応した端末では、書き出し中に画面が消えないようにする
- **保存の三段構え**: 共有シート → 失敗したらダウンロード → それも駄目なら「別タブで開く」から長押しで保存
- **完成した動画をその場で再生**して確認できる

なお、書き出し中に他のアプリへ切り替えるとブラウザが描画を止めるため、必ず画面を表示したままにすること。

無劣化かつ短時間で処理したい場合は、iOS ネイティブの `AVMutableVideoComposition` に置き換えるのが本筋。減点データは `{ value, at, shot }`、難度データは `{ g, d, val, at }` の配列で保持しているので、そのまま移植できる。
